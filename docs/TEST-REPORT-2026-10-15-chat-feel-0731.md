# TEST-REPORT — 0731 PD 集群「体感速率」实测（chat 流式，2026-10-15）

- **日期**：2026-10-15 07:40（集群 = 3P5D ★综合最优形态，router `10.66.3.32:8001`）
- **目的**：量化"**体感速率**"——用户对 chat 的真实体验 = **TTFT（等待感）× ITL 分布（流畅度/卡顿感）
  × 出字速率（视觉爽感）× 多轮连续性**；提供可复现测试法与判读标尺。
- **测试工具**：`tools/feel_test.py`（本仓，流式 curl 直测；输出 `/tmp/feel-results.json`）
- **配套**：sglbench chat 画像场景（`prod-chat-c1/c16/...`）提供标准化可比基线（全量入 DuckDB）。

## §1 体感指标定义与判读标尺

| 指标 | 定义 | 用户感知 | 判读标尺（经验） |
|---|---|---|---|
| **TTFT** | 发问→首 token | "响应快不快" | <0.5s 即时 · 0.5-1s 好 · 1-3s 可接受 · >3s 明显等待 |
| **ITL 中位** | 相邻流式 chunk 间隔中位 | "打字流畅度" | <20ms 流畅（≈65+字/s）· 20-50ms 尚可 · >50ms 顿 |
| **ITL p99** | 间隔 99 分位 | **"卡顿感"**（长尾主导体感） | >0.3s 可感知 · >1s 明显卡顿 |
| **出字速率** | 输出字符/净生成秒 | "打字机速度" | >100 字/s 爽 · 50-100 良好 · <30 难受 |
| **多轮 TTFT 稳定** | 各轮 TTFT 波动 | 对话「连贯不连贯」 | 轮间波动 <2x 为佳 |

### 关键观察
1. **两档 TTFT**：**热态 0.21-0.42s（即时档）** vs **隔置后首发 2.6-2.9s（冷态档）**
   ——A2/A3 为长间隔后首跑（DSPARK/JIT 冷相位），B 轮与 A1 热态全部 ≤0.42s。
2. **ITL 中位 3-41ms**（多在 10-39ms）→ **流畅档**；p95 稳定在 ~50-60ms。
3. ⚠ **偶发 p99 大卡顿**：A2/B-R1 各出现一次 **~3.2-3.3s 单点停顿**（MACA/DSPARK 相位抖动类，
   与历史"长尾 hitch"同族）——中位体验优异但**长尾可感知**（改进候选：chunked/conservativeness
   或引擎侧 hitch 排查）。
4. **多轮连续性优秀**：R1→R3 TTFT 0.21→0.26s（波动 <25%），带历史轮出字 124-129 字/s。
5. 短问答最快（144 字/s）：小 batch 下 DSPARK accept 率高（历史标定 accept 0.78-0.83）。

## §6 两大短板：根因实验 + 优化方案（2026-10-15 09:4x 追加）

### 6.1 短板①「冷态首发」——热态衰减阈值定位实验

| 实验（本次） | 条件 | TTFT | 结论 |
|---|---|---|---|
| T1 | 闲置 ~10min 后首请求 | **0.247s（仍热！）** | 10min 闲置**不产生冷态** |
| T2 | 紧接 T1 | 0.208s | 热 |
| T3 | keep-alive(30s) 运行中闲置 200s | 0.219s | 保活有效 |
| T4 | 紧接 T3 | 0.196s | 热 |
| 实验A | 6 连发不同 prompt（跨引擎落点探测） | min 0.17 / max 0.36 / 中位 0.26s | **per-engine 冷态本轮亦未复现** |

**对照早晨实测（§2）：闲置 ~27min → 首发 2.6-2.9s**。→ **热态衰减阈值 ∈ (10, 27] 分钟**；
早晨的 A2/A3/B-R1 慢点 = 超过衰减阈值后的冷态 + 长尾叠加（当时引擎处于轻探针状态约半小时）。

### 6.2 短板① 优化方案：**feel_warmup.sh v2（本仓 tools/）**

- **设计依据**：阈值 ∈(10,27]min → **保活间隔 300s（5min）** = 阈值 1/5，5x 安全裕度；
  **必须打 `/v1/chat/completions` 生成路径**（router `/health` 探针不触发生成链路——这是最容易
  踩的坑）；每轮 2 发覆盖多引擎落点。
- **部署**（接入层常驻）：
  ```bash
  nohup bash tools/feel_warmup.sh 300 &        # 默认即可
  # 推荐生产：systemd timer 或 k8s CronJob 每 5min 一发（内容=1-token 生成）
  ```
- **验证状态**：T3/T4 已验证保活下闲置 200s 全热 ✓；**27min 级长闲置的端到端验证留作后续**
  （需守候实验窗）。**成本**：每 5min 2 次 1-token 生成 ≈ 忽略级（<0.01% 容量）。
- ⚠ **残余风险**：per-engine 维度（5 个 decode 引擎各自衰减）尚未精确定位——warmup 走 router
  落点随机，长尾引擎可能仍偶发冷态；根治需按引擎直打（受 PD 配对限制，待后续方案）。

### 6.3 短板②「偶发 p99 卡顿」——定量基线实验

| 指标（90s 连续流，单流） | 实测 |

| ITL 中位 / p95 / p99 | 36ms / 51ms / **283ms** |
| hitch >0.3s | **2 次（3.6/min）**，最长 **304ms** |

**对照早晨电池（~3.2s 级卡顿）**：早晨长尾明显更重——**卡顿与冷态同源于"长闲置后的热态回退"**
