**共性机制（三份 capture 铁证）**：
```
KV/SWA 池用量 → 1.00（饱和）
→ 某 rank 调度停滞 → MCCL/Gloo/TCPStore 连接被重置（"Connection reset by peer"）
→ dp-attention all_gather 集体抛错 → 全组 4 pod 同时崩溃 (-3)
→ 容器内自动重启失败（prometheus DuplicateTimeseries bug，见 §4）
→ LWS 整组重建（5-25 分钟恢复）
```
「断连 peer」每次不同（34/35/33…）—— **不是坏节点，是负载下通信层集体过载**；变量是并发数，不是速率（4.0/5.0 同样崩）。

## 2. KV 池容量模型（实测反解）

拓扑：decode dp=4（每节点 1 rank），`mem-fraction-static=0.75`。

| 参数 | 值 | 说明 |
|---|---|---|
| `max_total_num_tokens`（full 池） | **~202K tokens/rank** | 混合注意力中「全注意力层」的 token 槽位 |
| swa 池容量 | `full × swa_full_tokens_ratio` = **20.3K**（r=0.1） | 滑动窗口层 token 槽位 |
| **SWA 层每 token 显存** | **≈ full 层的 37.5 倍** | 由 r=0.1/0.4 两组实测（201743/59904）反解 |

**容量上限（4096 输入 / 2048 输出）**：每请求 ~805 swa tokens → swa 池先饱和：

| 并发 | 每 rank 请求 | swa 峰值 | 实测结果 |
|---|---|---|---|
| 64 | 16 | ~0.64 | ✅ 成功（1747 tok/s） |
| 80 | 20 | ~0.79 | 验证中 |
| 96 | 24 | **0.99** | ❌ 崩溃 |
| 128 | 32 | >1.00 | ❌ 崩溃（多次） |

→ **安全上限 ≈ 85 并发（swa≤85%）**；**64 = 推荐生产水位**。

**容量上限（65K 长上下文）**：每请求吃 ~65K full tokens → full 池先饱和：
full 202K ÷ 65K ≈ **3 请求/rank = 12 总量**为绝对上限；32 并发（8/rank）必然崩（实测），
16 并发（4/rank）也崩（实测 19:56），安全值 ≤ 8-12（验证中）。

## 3. swa-full-tokens-ratio 实验（2026-10-02 晚，已回滚）

**假设**：SWA 池先饱和 → 提高 ratio 扩大 SWA 池。
**做法**：新增适配层 `_override_literal` 字面量回写（launcher-configmap.yaml），
把厂商硬编码的 `--swa-full-tokens-ratio 0.1 #0.4` 改写为 0.4，实机生效（日志可证）。

**实测判决**：

| ratio | full 池 | swa 池 | 结论 |
|---|---|---|---|
| 0.1（原值，已回滚） | 201,743 | 20,321 | ✅ 最优 |
| 0.4（实验） | **59,904 (-70%)** | 24,000 (+18%) | ❌ 灾难 |

**数学结论**：`swa容量 = B·r/(A/B+r)`（A/B=0.0267），随 r **次线性**增长、上界 25K；
r=0.1 时 swa 已占总预算 79%。**厂商脚本里的 `0.1 #0.4` 是刻意校准，不是笔误**。
比例旋钮已用尽 → 提并发的真正杠杆只剩 **fp8 KV（未验证）或扩容硬件**。

## 4. 代码级缺陷清单（证据齐全，可报障/修复）

1. **★ 根因：retract→offload_kv_cache→NotImplementedError**（2026-10-02 21:01 抓到完整栈）：
   `release_req`（schedule_batch.py:2262）只判断 `disaggregation_mode == "decode"` 就**无条件**
   调用 `req.offload_kv_cache(...)` → 混合 SWA 池 `swa_memory_pool.get_cpu_copy` 未实现
   （memory_pool.py:788 `raise NotImplementedError()`）→ Scheduler 崩 (-3) → 全组级联。
   **任何 retraction 事件 = 必崩**（96/128 并发、65K×8、以及凌晨空闲期自发崩溃均此机制；
   早前观察到的 "Gloo/TCPStore connection reset" 都是次级现象——peer rank 已先行崩溃）。
   **连带缺陷B**（修复A后暴露）：`resume_retracted_reqs`（decode.py:605）无条件 `load_kv_cache`
   → `AttributeError: 'Req' object has no attribute 'kv_cache_cpu'`——本 fork 的 disagg-decode
   retract/resume 流程**硬依赖 CPU offload**。
   ✅ **已修复（patch v2，4 处替换，2026-10-02 21:3x 上线并验证）**：
   ① release_req 补 feature gate（本部署=False）；② release 后 retract 改走 abort 通道优雅降级
   （无 offload 能力时直接 abort 被选中的请求，客户端收 500、服务不死）。
   boot 时 Python 幂等注入 + `py_compile` 校验 + 失败还原（decode.yaml command 段，镜像更新后删除；
   镜像补丁备料见 `docs/patches/0001-schedule_batch-retract-offload-fix.patch`）。
   **验证（21:44/22:37，两个原 100% 崩场景）**：
   ① 128@5.0×300：✅ `300/300 成功，2050 tok/s`，0 崩溃 0 客户端错误；268 次 retract 压力事件
   （swa 池 17 次触顶）全部由 abort 通道消化（`#retracted_reqs: 0`）。
   ② 8×65K×100：✅ `100/100 成功`，输入 2550 tok/s / 输出 283 tok/s / TPOT 20.5ms；27 次 retract
   （full 池多次触顶 1.00）优雅降级；TTFT 48s（压力代价）。
2. **prometheus 重复注册**（`sglang/srt/observability/func_timer.py:35`）：
   崩溃后进程内重启 `Histogram` 重复注册 → `DuplicateTimeseries` → **重启必然失败**，
   恢复只能等 LWS 整组重建（中断时间从 ~1min 拉长到 5-25min）。修法：注册前 `unregister`/判重。
   （与 #1 独立；#1 修复后崩溃频率大降，但此缺陷仍在。）
3. **MCCL/Gloo 集体通信脆弱**（dp-attn 每步 all_gather，任一 rank 瞬断=全组崩）：仍是潜在风险面；
   #1 修复前的崩溃都由此放大成全组事件。
4. 附带：`--prefill-round-robin-balance` 已 deprecated（镜像启动警告，待镜像更新）；
   `SGL_DISABLE_TP_MEMORY_INBALANCE_CHECK` 已废弃 → 应改用 `SGLANG_ENABLE_TP_MEMORY_INBALANCE_CHECK=0`。

**排除的伪解法（2026-10-02 实测）**：`--disable-cpu-offload` 参数在本 build **不存在**
（加上会 argparse 报错）；提高 `swa-full-tokens-ratio` 方向相反（r=0.4 → full 池 -70%）。

## 5. 日志持久化（2026-10-02 已改造上线）

- 原机制（hostPath + `tee -a`）实际**一直在追加**（hostPath 有 24 代际完整历史），

## 7. 结论与建议（patch v2 修复后更新）

- **修复效果**：128 并发 @5.0 由"必崩"变为 **300/300 成功、2050 tok/s**（268 次 retract 压力事件经
  abort 通道优雅降级、0 客户端错误）；当日全部崩溃（含凌晨自发）均由本双缺陷解释，与网络/硬件无关。
- **性能水位（选档依据，不再是崩溃红线）**：4096/2048 负载每请求 ~805 swa tokens（swa 池 20.3K/rank）——
  并发 ≤96 时 retract 不频繁（**64 = 舒适水位** ~1747 tok/s；**128 可用但需容忍 TTFT 升至 ~12s** ~2050 tok/s）；
  65K 长上下文受 full 池约束（~3 请求/rank），**8 并发已验证 100/100 通过**（TTFT ~48s、输入 2550 tok/s）。
- **镜像级固化（建议）**：把 `docs/patches/0001`（+ 候选 `0002` func_timer 防重启失败）打入镜像
  （沿用原 tag，imagePullPolicy 已 Always），随后删除 decode.yaml 的 boot 补丁段；顺手修
  `SGL_DISABLE_TP_MEMORY_INBALANCE_CHECK` 废弃变量。
- **报障建议（厂商）**：① 本双缺陷（docs/patches/ 附参考修复）；② retract/resume 硬依赖 CPU offload
  的设计不适配混合 SWA 池；③ MCCL/Gloo 级联放大（单 rank 崩溃拖全组重建）；④ prometheus 重启注册 bug。
- **已穷尽的调参路径**：swa ratio（0.1 最优，§3）、mem-fraction（OOM 边界）、rate（无影响）、网关选型（无影响）。
